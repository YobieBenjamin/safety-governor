# Addressing the external audit (2026-10-23)

An external adversarial review (see `audit/external-2026-10-23/` once published, and the memo in the
project) found 28 findings: real, concrete, code-level holes in the authorization contract, several
experiments that measure the wrong thing, open hardware and persistence obligations, and governance
and economics that are not yet demonstrated. The central idea stands; the assurance case did not yet
earn its strongest claims. The findings are being closed, each with a discriminating test, and the
negative results and open obligations are kept on the record rather than smoothed over.

## One command (on the Mac)

```bash
bash ~/safety-governor/tools/agents/run_audit_fixes.sh --detach
```

It stamps the PolyForm / CC BY-NC license across every repository, publishes the 28 findings as
labelled GitHub issues, and runs them as coding agents in dependency-ordered waves through the
existing program gate (verify, a local second read, a bounded cloud review, CI green, dependencies
merged) so nothing merges that is not clean. Follow it with `--status`; stop it with `--stop`;
resume at a wave with `--from N`. `--stamp-only` and `--publish-only` do just those steps.

## The order (the audit's own section 6 roadmap)

| Wave | What | Findings |
|---|---|---|
| 1 | The executable authority contract | F01 F02 F03 F04 F05 F06 F10 F11 (SG); F07 F08 F22 (HS) |
| 2 | Honest experiments and claims | F12 F13 F23 F04-audit F24 F25 (SG); F09 (safety); F27 (Watermark) |
| 3 | Persistence and hardware contracts | F14 F15 F16 F17 F18 F19 F20 (SG) |
| 4 | Build evidence and governance | F21 F26 F28 (SG) |

The order matters: more physical implementation of the wrong authorization contract would make the
repair more expensive. Each finding's brief (in `tools/github/audit-fixes.json`, generated by
`tools/github/make_audit_fixes_spec.py`) carries the exact location, the concrete failure trace, the
fix, and the one discriminating test the agent must add and make pass.

## The rule for every fix

Defensive hardening only. Add a test that fails on the current source and passes after the fix, at
the acceptance command the brief names. Never weaken, skip or delete an existing test. The guarantee
is a list of specific obligations with evidence, not a passing test count.

## Head start already in the container bundle

- **F03 (NaN budget) is fixed and tested.** `crypto.canonical` now refuses non-finite numbers
  (`allow_nan=False`), a shared `crypto.finite_number` rejects bool, NaN and infinity, and the
  ledger, the typed constraint check and the governor budget branch all use it. See
  `tests/test_f03_nan_budget.py`. The full suite stays green.
- **License stamped** in safety-governor and hardware-and-silicon (PolyForm Noncommercial 1.0.0 for
  code, CC BY-NC 4.0 for docs), with SPDX headers on own-source files and the five root files. The
  launcher stamps the remaining repositories on the Mac.
- Other findings being seeded in the container land in the same bundles; the Mac program re-verifies
  them and does the rest under the review gate.

## What this does not claim

Closing these findings does not make the chip a working safety guarantee. It makes it an honest
research implementation with its known defects repaired and its open obligations written down. The
must-have property, per the audit, is one exact protected action that cannot be performed without
current, independent authorization, demonstrated through failures and recovery on real hardware, and
compared against an HSM/TEE/controller baseline. That is program direction (waves 5 to 7 in the
audit), not a code fix, and it is tracked in `docs/18-viability-and-open-questions.md`.
