# Exit register: every path that reaches or leaves a GPU (October 2026)

Claim P (docs/20, experiment P2) holds by enumeration or not at all. This is the enumeration for an HGX H100/H200 eight-GPU baseboard and a GB200 NVL72 compute tray, with the retrofit question (a governor module in the DC-SCM 2.x slot) answered in the same rows. It builds on `docs/research/board-lever-register.md` (cited as BLR + row) and `docs/research/nvswitch-management.md` (cited as NSW + section); their primary sources are repeated in the key at the end. This run did no new web research, so a claim is only as good as those two registers; where they say UNKNOWN, so does this one.

## How to read it

- **status**: `governed` (a lever exists that stops or limits the path), `bricked` (no signal path exists or it is fused off; the how is in the lever column), `recorded-gap` (not governed at the rack tier, named in the objectives, closed only at the integrated tier), `unaccounted (NDA)` (public documents cannot settle it; the HGX design guide DG-10333-001, the baseboard pin map, the DC-SCI pin spreadsheet or a board schematic would), `unaccounted` (nothing settles it and no document is known that would; the test fails on this).
- **evidence**: VERIFIED (primary source quoted in the cited register), PARTIAL, UNKNOWN, DESIGN (the governor's own design intent, nothing external).
- **from_module**: can a module on the DC-SCI connector drive this lever, directly or through LTPI to the host-board CPLD, on at least one publicly documented DC-SCM 2.x host board. `yes`, `no`, or `NDA`. `yes` needs a public document that shows the wire on a named board. No public host-board wiring to a GPU lever was found in the two registers, so no lever row says `yes`.
- **undo_paths**: what else on the board can drive or reverse the same lever.
- **class**: `lock` (the module can drive it and nothing outside the governor can reverse it) or `witness` (it observes and may act, but something it does not sit in front of can undo it, or it cannot reach the lever). Every lever row below is a `witness` until a board document says otherwise.

## What the register says

Counts at this commit: `governed` 16, `recorded-gap` 2, `bricked` 2, `unaccounted (NDA)` 14, `unaccounted` 0. The test counts them from the table.

1. **Rack-tier claim P.** Zero rows are `unaccounted`, but fourteen are `unaccounted (NDA)`, and several are the ones that matter most against a hostile host: out-of-band bus ownership (X21), firmware update (X23, X24), debug (X11, X12), the Grace C2C link (X04, and X31 for the host-side exit the audit 3 fixes added), the BMC's NC-SI sideband and any BMC read of host or GPU memory (X34), and the LTPI transport itself (X30). Claim P is not yet established by enumeration; it is established for the switch, DPU, storage and board-level power paths and open for the rest. `governed` here means a lever exists that stops or limits the path (the signal is named and, where public, verified), not that its routing is public: X13 and X14 carry UNKNOWN routing, several rows are PARTIAL, and no governed row rests on the governor's own design intent (X05-X07 cite the switch/DPU path lever, not DOCA Flow or the model key). The model's `jtag` and `debug` exits are bricked "by policy" in `govsim`; this register finds no public evidence for how, so those two stay NDA rows.
2. **No lever is a lock on the retrofit.** Every governed row is a `witness`: from_module is `NDA` (routing is in the design guide) or `no` by specification (X19 and X27: the DC-SCI carries no per-endpoint PERST and no REFCLK to the module, BLR F2), because the two registers found no public host board that wires a DC-SCI signal to a GPU lever, and each lever has an undo path the governor does not sit in front of, mostly the BMC, which on GB200 owns `PWR_BRAKE_L-O`, `RUN_POWER_EN-O` and `SYS_RST_IN_L-O` today. The module-swap retrofit works as a lock only if the module replaces the BMC's authority over those lines (a board where the module sits between the BMC and the CPLD) or the BMC is made unable to reach them. That is a board-revision question, not a slot question.
3. **What the slot does give.** The DC-SCI has the transport: 18 I2C ports, two UARTs, two NC-SI, JTAG, SGPIO, and LTPI with 16+16 GPIO each way (BLR F1, F3). It does not carry per-endpoint PERST (BLR F2), and the single node PERST flows toward the module. So per-GPU reset from the slot is `no` by specification; everything else is the CPLD firmware's mapping, which is `NDA`.
4. **Disproof status.** The disproof "no lever reachable from the module slot on any public DC-SCM 2.x board" is neither confirmed nor refuted: this run surveyed no public host boards beyond the NVIDIA MGX subset (BLR C5, F4), which publishes only a pinout subset. Open item for a run with web access: survey public DC-SCM 2.x host boards for any DC-SCI GPIO, I2C or SGPIO net that reaches a power-brake, reset or enable input.
5. **The "second module" wording.** docs/03 s1 and hw/pcb/rack-integration.md say the governor rides as a second module or a mezzanine on the existing one. Whether a real host board carries one DC-SCI connector per slot (so that a second module needs a second slot and the mezzanine form fits one slot) is not settled by the public record: BLR F4 shows the MGX subset publishes only a pinout subset, so the connector-per-slot count is an assumption to check against a host-board pinout, not a finding of this run.

## Host-side exits (added 28 October 2026)

Adversarial audit 3 added three host-side exits to the model (`nvlink_c2c`, `host_nic`, `bmc_nic`: no switch of their own,
metered against one shared host allowance, output sealed to the egress endpoint; `docs/research/host-side-exits.md`).
Rows X31 to X34 record what NVIDIA's public documents say about each, drafted from a research pass on 28 October 2026 and
checked by Yobie Benjamin the same day. X31 (NVLink-C2C) and X34 (BMC NC-SI sideband and BMC memory access) are not settled
publicly; X32 (GPUDirect) and X33 (the BMC's dedicated port) have public levers that host root or a BMC administrator
can undo, so the governor must attest those settings, not own them.
