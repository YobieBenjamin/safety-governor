# Audit of the Safety Governor design, October 2026

Two passes. The **first pass** was the author's own deep dive over every claim in `docs/`,
`govsim/`, `rtl/`, `hw/` and the blog's Part 4, looking for statements that were not true
(hallucinations), conditions the model made true by construction rather than by mechanism
(fake conditions), and claims nobody can verify yet that were written as facts. The **second
pass** was done by two independent reviewers who had not seen the design being written: one
checked every external fact against primary sources, the other checked the design against
its own code, tests and RTL, including forty-eight single-point mutations of the model and
the RTL run against the test suite. The second pass found that two of the first pass's
"corrections" were themselves wrong, that the design's single most load-bearing number was
off by an order of magnitude, and that twenty mutations survived the suite. Everything below
is what was found, what was checked against which source, and what changed. The last section
lists what is still a target, an estimate or an ask.

## 1. The second pass: what the first pass got wrong

| # | First-pass claim | What is true, and the source | What changed |
|---|---|---|---|
| REVIEW-SIGNATURE-COST-UNDERSTATED | "Under 2 ms per ECDSA P-384 signature on an OTBN-class coprocessor at 100 MHz", and the bench charged 1 ms, giving "0.4 percent overhead" | OpenTitan publishes OTBN cycle counts: a constant-time ECDSA-P384 sign is **1,697,985 cycles**, which is **17 ms** at Earl Grey's 100 MHz core clock (P-256: 704,126 cycles, 7 ms). Per-response signing therefore caps at about 59 responses per second per engine, and the first-pass "0.4 percent" rested on a number eight and a half times too small. Source: opentitan.org, OTBN performance table | `04-specification.md` §9 states the published figure; `govsim/bench.py` prices it exactly and now reports three honest numbers (firmware share of GPU time, 0.01 percent; signing-engine utilization with batching, 34 percent; record latency, 67 ms); batching is the design's default path with a 50 ms window; the blog's cost paragraph was rewritten |
| REVIEW-OTBN-SUPPORTS-EDDSA | "OpenTitan's OTBN has no Ed25519 program" (first-pass item 12) | OpenTitan's OTBN crypto library carries an Ed25519 implementation (`sw/otbn/crypto/25519.s`: `ed25519_gen_public_key`, `ed25519_sign_stage1/2`, `ed25519_verify_var`, RFC 8032) alongside X25519. | REVIEW-SENTRY-SCOPE-MISSTATED | NVIDIA's Sentry "runs on the same DPU" as any BlueField | Sentry was announced in September 2026 as part of NVIDIA's open agent safety platform and is built for BlueField-4; it does not run on the BlueField-2/3 DPUs in today's racks | `03` §6 dates and scopes it |
| REVIEW-DIE-AREA-OVERSTATED | "Die area ~10 mm² for the control core" | `hw/librelane/governor_core/config.json` hardens a 1.4 × 1.4 mm die, 1.96 mm². Ten square millimetres is the shuttle harness's user area | `04` §11, the die figure |

## 2. The second pass: the model and the RTL against their own documentation

The reviewer ran 48 mutations (39 of the model, 9 of the RTL), each disabling one mechanism,
against the full suite. Twenty survived with no failing test. Each of those, and each
documented guarantee the code did not provide, got a fix and a test. The fixed tree was
re-mutated: all nineteen listed below are now caught.

| # | What the documentation promised | What the code did | What changed |
|---|---|---|---|
| REVIEW-UNCOMMITTED-EPOCH-KEPT-RUNNING | A governor that cannot acknowledge an epoch change is halted, not left on the old rules | A governor that staged the new image but never received the commit kept running on the old rules indefinitely, because the new-epoch heartbeat was accepted under the staged epoch with no deadline | The staged epoch is accepted only until `fabric.epoch_deadline_s` (10 s) after staging; then the heartbeat is refused and the governor halts as `EPOCH_STRAGGLER` on the rung the policy names. Staging is durable. Test: `test_contract_partitions_end_safe::test_staged_but_uncommitted_governor_is_expelled_at_the_deadline` |
| REVIEW-LOADER-TRUSTED-DECLARED-INPUTS | The loader refuses a rulebook whose rules name an input with no register row | Only the author's self-declared `inputs` list was checked; a constraint that named a list without declaring it loaded anyway | Inputs are derived from constraints (`in_list`, `not_in_list`, `digest_of`), observers and the budget key, unioned with the declared list. Tests in `tests/test_contract_assumptions_register_complete.py` |
| REVIEW-POWER-CYCLE-CLEARED-HALT | A halt is cleared only by the authority after the cause is logged | The cause and the rung were not durable; a power cycle came back in HALTED_INITIAL and the next heartbeat ran the GPU | Cause, rung, loop-switch state and timers are durable; boot re-enters the rung with the switch open. Test: `test_contract_halt_reaches_every_gpu::test_power_cycle_does_not_clear_a_halt` |
| REVIEW-EPOCH-WRITABLE-AS-ATTRIBUTE | The host has no path to write the epoch | The test checked that no handler was literally named `EPOCH_SET`; the epoch was a plain attribute | `epoch` is a read-only property set only by `_accept_policy`; the test runs every mailbox command and asserts the epoch moves only through a valid stage and commit |
| REVIEW-DEVICE-SECRET-ORDINARY-ATTRIBUTE | The device secret is readable only by the key-derivation engine | The test checked three attribute names; `_uds` was an ordinary attribute | The UDS lives in a closure; the test walks every attribute recursively against a known seed |
| REVIEW-SWITCH-TEST-ASSERTED-STUB | The host cannot reprogram a switch; capabilities carry an integrity tag checked at insertion | The test asserted a stub that always returned False; the MAC check had no test | Tests for forged, altered and foreign-key capabilities; the stub is gone |
| REVIEW-FORGED-CHECKPOINTS-ACCEPTED | Checkpoints are cross-linked; forged rosters and checkpoints are dropped | The content assertion ended in `or True`; a roster was adopted without verifying the leader's signature; a forged checkpoint was recorded | Leader signature verified on ROSTER; forged ROSTER and CHECKPOINT dropped and logged, with tests; the `or True` is gone |
| REVIEW-CHECKER-PASS-FAKED-BY-TEST | At the integrated tier the in-GPU checker closes the descriptor-level gap | The pass was produced by the test closing the checker by hand; as programmed by the governor the same transfer passed | CONTRACT-DESCRIPTOR-LEVEL-ROSTER-GAP at the integrated tier is reported as a gap ("checker modelled; buffer-class policy not"), not a pass |
| REVIEW-OWNERLESS-BUDGET-DEFAULTED-LOCAL | One ledger owns a budget key | A budget key missing from `budget_owners` defaulted to the local governor, so four governors could each spend the whole limit | No default: an image whose rules name an ownerless budget key does not load. Test in `tests/test_contract_shared_budget_no_overspend.py` |
| REVIEW-UNPRESENTED-OUTPUT-INVISIBLE | The output channel's budgets cover the channel | At the rack tier the governor saw only what the runtime chose to present; bytes that left for the host unpresented were invisible | Output bytes now pass the governed PCIe switch port in the model; the governor compares bytes passed to the host with bytes presented and raises `OUTPUT_UNPRESENTED`, blocks output and closes the port when the difference exceeds the policy's slack. Tests in `tests/test_contract_leakage_within_budget.py` |
| REVIEW-HEARTBEAT-WINDOW-UNCLAMPED | A governor past the policy's heartbeat expiry enters safe mode | The expiry came from whatever window the authority signed; a one-year window was accepted | The window is clamped to `fabric.heartbeat_expiry_s`. Test in `tests/test_contract_partitions_end_safe.py` |
| REVIEW-MAILBOX-CHECK-ORDER-UNPINNED | Mailbox checks sequence, then epoch, then signature | The model checked the signature first; the RTL did not pin the order | Both check in the documented order and report the first failure; a two-defect frame test in each suite |
| REVIEW-COMMANDS-ACCEPTED-UNSIGNED | Every mailbox command is signed by the class the policy names | `REQUEST`, `CAP_REQUEST` and others took unsigned bodies; `CAP_REQUEST` could open any point to `host` | `REQUEST`, `CAP_REQUEST` and `ROSTER_JOIN` require the verified host enclave's signature with fresh attestation; `host` is a peer only on the PCIe point; `VERIFY_GPU` returns a governor-signed result; the commands authenticated by their payload (`POLICY_*`, `VERIFY_*`) are named as such in `04` §3 |
| REVIEW-COMMAND-HANDLERS-MISSING | Nineteen mailbox commands, one handler each | Four were missing and two extra ones were undocumented | `END_MODEL`, `COMMIT`, `ROSTER_JOIN` and `EXCEPTION_DRAIN` implemented; `ALARM_RAISE` and `ALARM_CLEAR` are 0x14 and 0x15; a test checks every code has a handler and nothing else is reachable |
| REVIEW-LEVERS-RELEASED-AT-BOOT | Levers at power-on: brake and reset asserted, slot power off; the loop switch open | Model and RTL released reset and powered the slot at boot; the RTL switch started closed | Model, RTL, pinout and docs agree on the boot state; the RTL switch starts open and closes only when armed; tests assert every lever per rung |
| REVIEW-TIMER-OVERFLOWS-RTL-WIDTH | Timers in seconds; a 16-bit RTL timer | 300 s at microsecond ticks does not fit sixteen bits | The RTL derives a millisecond tick from the counter; timers are 20-bit milliseconds |
| REVIEW-MONOTONIC-COUNTER-NEVER-TICKED | A live, persisted monotonic counter stamping messages | Never ticked or saved; quotes carried zero | Ticked in `tick()`, persisted, and stamped on fabric messages, records, rosters and tickets |
| REVIEW-RESTART-REOPENED-REPLAY-WINDOW | Fabric and heartbeat replay protection | Last-seen sequence numbers were volatile; a restart reopened the replay window | Persisted; a restarted sender resumes above its last number; restart-replay tests |
| REVIEW-RULES-KEYED-BY-WORKLOAD | Rules keyed by the fingerprint | Impossible as defined, because the fingerprint contains the epoch of the image the rule is in | Rules are keyed by the workload measurement `H(gpu firmware, host firmware, model)`; the fingerprint `H(workload, epoch)` binds tokens and tickets; an exact rule beats a wildcard, with a test |
| REVIEW-ENDPOINTS-TRUSTED-ONE-GOVERNOR | Endpoints verify any governor's ticket | Endpoints held only the first governor's key | Endpoints hold the rack's governor key set; a non-leader's ticket executes, with a test |
| REVIEW-METER-NEVER-READ | The meter is read from the GPU | Never read in any simulated path | Read on every tick; test for monotonic counters and no host write path |
| REVIEW-DOCUMENTED-BEHAVIOUR-UNTESTED | Untested but documented behaviour | Stale-epoch frames, capability expiry and stale tags, rate windows, the hop limit, the relay signature, governor-side commit checks, the fused policy-version counter, the self-clearing governor, the forged CLEAR, per-step durability | Twelve new tests, including a store fault-injection hook that fails the save at every point of a request in turn |

Not changed, and said so in the documents: an automatic release and re-request of shared
budgets when their owner leaves the roster (the behaviour is fail-safe: the spend fails);
the member-count beacon that would detect a governor jumpered out of the loop (specified,
not modelled); member countersignatures on the roster.

## 5. Still unverified: targets, estimates and asks, not facts

- **Whether a given SXM baseboard brings out a hardware power-brake signal, and whether it has per-slot power control.** Board-specific; the design records both per board and the floor is reset.
- **What the HGX baseboard connector carries** beyond the management bus. The design assumes only what the OEM's own documentation shows; everything else on the baseboard is an ask to NVIDIA.
- **An out-of-band port disable on NVSwitch.** An ask. Today's authority is partition membership through Fabric Manager plus switch reset.
- **Halt-loop timing** (100 µs sense period, two periods to declare loss, 1 ms end to end over 72 governors). Design targets until the Phase 2 bench measures them.
- **Signature cost on the governor's own engine.** OpenTitan's published OTBN figure is the price used; a dedicated ECC engine would be faster and none is assumed.
- **The one-percent overhead on a whole protected deployment** (REQUIREMENT-DEPLOYMENT-OVERHEAD-UNDER-ONE-PERCENT). A model today; the Phase 2 measurement replaces it.
- **Cost and schedule** (ChipFoundry's listed slot price; about a year to a measured prototype; low millions and 18 to 24 months for product silicon). Class estimates, not quotes.
- **Side-channel resistance of the crypto engines** in the prototype. Not proven; the product node enables countermeasures.
- **The prototype's tamper resistance.** None by design: sky130 has no open OTP macro, so the UDS is injected at power-up by an external secure element. Recorded in the assumptions register.
- **Not modelled:** the loop member-count beacon; release and re-request of shared budgets on owner departure; roster countersignatures.

## 6. How to re-run the audit's evidence

```bash
./run.sh                      # 159 hypothesis tests, 20 RTL block tests, Verilog regenerated, results/report.md
python -m govsim.cli bench    # firmware share, signing-engine utilization with and without batching, record latency
python -m govsim.cli demo     # a narrated rack, with the model parameters labelled as such
python3 docs/figures/make_figures.py   # the six figures, from the facts the text states
```

The mutation scripts the second pass used are not part of the repository; the tests they
produced are.
